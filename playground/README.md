# Playground

The verification stand for the generated declarations in `mui-kotlin/src/jsMain/kotlin/**`. Every sample is a
small React page that uses a slice of one generated package at real call sites. Compiling the playground (CI does,
through `./gradlew build`) proves the call sites type-check; opening it in a browser proves what only running can:
that runtime keys exist, that callbacks are actually called, that state helpers resolve to the right overload.

## Layout

```
playground/src/jsMain/kotlin/playground/
  App.kt              main(): mounts the shell
  MissedWrappers.kt   typed write-only extensions for props/attributes missing from kotlin-wrappers
  shell/              routing, sidebar, index, sample frame, StatusLine / CheckList, Registry.kt
  samples/<library>/  one <Subject>Sample.kt per sample, package playground.samples.<library>
```

- `shell/` is infrastructure and must not import `mui.*`, `muix.*`, `baseui.*` or `dateio.*` — a broken
  declaration should take down its sample, not the whole stand.
- `shell/Registry.kt` declares the libraries and the ordered `samples` list; it is the only list of samples.
- `shell/Versions.kt` is generated by `:playground:generateVersions` from every `*.version` property in
  `gradle.properties` (into `playground/build/generated/playground/kotlin/`). Do not write it by hand.

## Conventions

- File `samples/<library>/<Subject>Sample.kt` declares `val <Subject>Sample: Sample` — metadata (`id`, `library`,
  `title`, `kind`, `covers`, `fileName`, `refs`, `notes`) plus `content = FC<Props> { … }`. Helpers live next to it
  without the `Sample` suffix.
- Sample ids are kebab-case. The global key is `<library>/<id>`; the frame carries it as `data-sample="<lib>/<id>"`.
- Sample ids are unique across all libraries, so `<sampleId>-<what>` DOM ids stay unique on `#/all`.
- New DOM ids are `<sampleId>-<what>` (`menu-status`, `slider-status`). Existing ids and classes referenced from
  the work logs (`bui-*`, `runtime-*`, …) stay verbatim.
- Components are `val X = FC<XProps> { … }` with `external interface XProps : Props`. No extension functions on
  `ChildrenBuilder`, no `asDynamic()` outside `MissedWrappers.kt`; add a typed write-only extension there instead.
- State goes through `StatusLine` (`<p data-status>` with `key=value` fields) or `CheckList` (`<li data-check="pass|fail">`),
  never ad-hoc text or `console.log`. Mount `CheckList` unconditionally at the top level of the sample content; a check
  that can only be computed from the committed DOM mounts its `CheckList` after the first commit instead
  (`pickers/PickersSectionListSample.kt`).
- The frame owns the heading and the metadata; samples do not render their own title.

## Routes

| Hash | Shows |
|------|-------|
| `#/` | Index: every sample with library, kind, covers and source path |
| `#/all` | Every sample, one after another — the smoke run |
| `#/<library>/<sample>` | One sample in its frame, e.g. `#/baseui/menu` |

An unknown hash renders a not-found message (`[data-not-found]`) above the index.

## Console lines

These are the lines to assert on:

```
[playground] <lib>/<id> mounted                       once per frame
[playground] <lib>/<id> <checkId>: P/T PASS           per CheckList; console.error when P < T
[playground] all: N samples mounted, P/T checks PASS  on #/all, once the checks settle
```

The `all:` line is logged once the checks settle (~200 ms after the last `CheckList` mounts), so check lists that
register after the first commit are counted. `#/all` also renders the same numbers as
`<p id="all-summary" data-status>samples=N checks=P/T</p>`.

## Add a sample

1. Create `samples/<library>/<Subject>Sample.kt` with `val <Subject>Sample: Sample`; fill `covers` with the exact API
   surface it exercises and `notes` with what only running it proves.
2. Add one line to `samples` in `shell/Registry.kt`.
3. Compile, open `#/<library>/<id>` and `#/all`, and check the console lines above.

## Commands

```bash
./gradlew :playground:jsViteDev                            # dev server, http://localhost:5173 by default
./gradlew :playground:jsDevelopmentExecutableCompileSync   # rebuild the bundle the dev server serves
./gradlew :playground:generateVersions                     # regenerate Versions.kt
```

`jsViteDev` does not rebuild Kotlin: after a code change run `jsDevelopmentExecutableCompileSync` and reload.
Read the port from the task output — Vite takes the next free one if `5173` is busy, and a stale server on `5173`
keeps serving the previous bundle.

## Driving it with Chrome DevTools MCP

1. `navigate_page` to `http://localhost:5173/#/<library>/<sample>` (or `#/all`).
2. `take_snapshot` to find elements by id or role; interact with `click` / `fill` / `press_key`.
3. `list_console_messages` and match the `[playground] …` lines; anything else at error level is a finding.
4. `evaluate_script` for DOM assertions:
   - `document.querySelectorAll('[data-sample]').length` — frames mounted (equals the registry size on `#/all`);
   - `document.querySelectorAll('[data-check="fail"]').length` — must be `0`;
   - `document.getElementById('<sampleId>-status').textContent` — the current `key=value` state;
   - `document.elementFromPoint(x, y)` over a target — diagnoses a click that lands on an overlapping element.
5. `take_screenshot` when the layout matters: a part rendered without its styles passes DOM queries but not a look.
